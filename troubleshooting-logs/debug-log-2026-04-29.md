## 一、换行符丢失问题

### 问题现象
- 用户上传 TXT 文件后，处理结果中所有段落合并成一段
- `\n` 和 `\r\n` 被替换为空格，段落结构丢失

### 问题根因

**文件**: `internal/processor/preprocess/preprocess.go:339-342`

```go
func cleanSpecialCharacters(result PreprocessResult) PreprocessResult {
    // 移除控制字符
    regex := regexp.MustCompile(`[\x00-\x1F\x7F]`)
    result.Content = regex.ReplaceAllString(result.Content, "")
    return result
}
```

`[\x00-\x1F]` 包含了所有 ASCII 控制字符，**包括 `\n`(0x0A) 和 `\r`(0x0D)**。该函数在预处理阶段运行，先于 `normalizeWhitespace`，因此换行符在后续任何阶段之前就已经被删除。

### 修复

```go
// cleanSpecialCharacters 清理特殊字符（保留 \n, \r, \t 以维护段落结构）
func cleanSpecialCharacters(result PreprocessResult) PreprocessResult {
    // 移除控制字符，但保留 \t(0x09), \n(0x0A), \r(0x0D)
    regex := regexp.MustCompile(`[\x00-\x08\x0B\x0C\x0E-\x1F\x7F]`)
    result.Content = regex.ReplaceAllString(result.Content, "")
    return result
}
```

使用 `[\x00-\x08\x0B\x0C\x0E-\x1F\x7F]` 替代 `[\x00-\x1F\x7F]`，显式排除：
- `\t` (0x09) — 制表符
- `\n` (0x0A) — 换行符
- `\r` (0x0D) — 回车符

**注意**：`basic_cleaner.go:160` 已有正确的正则 `[\x00-\x08\x0B\x0C\x0E-\x1F\x7F]`，而 `preprocess.go` 是另一个实现，两者未保持一致。

## 三、UI优化：Diff审核界面

### 问题现象
- 每条审核项的原文和建议都是一大段纯文本，用户要自己逐字对比
- 一千多字的内容混在一起，无法快速定位修改处

### 方案设计

1. **词级别 Diff 算法** — 中文/英文/数字/标点分词，LCS 计算差异
2. **Inline diff 渲染** — 删除部分红色+删除线，新增部分绿色高亮
3. **同类修改分组** — 相同(原文→建议)的修改自动归为一组
4. **组批量操作** — 每组[全部通过][全部拒绝]，调用已有后端 API

### 新建文件

**文件**: `web/frontend/static/js/diff-utils.js` (272行)

```
DiffUtils
├── tokenize(text)          — 分词：CJK单字/英文单词/数字/标点/空白
├── lcs(tokens1, tokens2)   — LCS DP表
├── diff(text1, text2)      — 生成[{type, value}]操作序列
├── mergeOps(ops)           — 合并相邻同类操作
├── renderInlineDiff()      — 完整diff渲染HTML
└── renderDiffPreview()     — 变更区域摘要渲染(组预览用)
```

**分词正则**: `[\u4e00-\u9fff\u3400-\u4dbf\uf900-\ufaff]|[a-zA-Z]+|[0-9]+|\s+|./g`

### 重写文件

**文件**: `web/frontend/static/js/modules/review.js` (709行)

核心变更：

| 功能 | 实现 |
|------|------|
| Diff 渲染 | `createGroupElement` 头部使用 `renderDiffPreview`（仅变更区域+上下文20字），展开明细使用 `renderInlineDiff`（全文） |
| 同类分组 | `groupReviewItems()` 按 `original|||suggested` key 分组 |
| 组排序 | 按出现次数降序排列（高频修改优先） |
| 折叠/展开 | 点击组头部切换 `.collapsed` |
| 组批量操作 | `batchApproveGroup(itemIds)` / `batchRejectGroup(itemIds)` 调用 `POST /files/:md5/batch-approve` |
| 全局操作 | 保留原有的"全部通过""全部拒绝"按钮 |
| 已处理项 | 筛选 `status !== 'pending'` 在底部分开展示 |

**分组数据结构**:
```javascript
groups = [{
  original: "原文文本",
  suggested: "建议文本",
  count: 12,   // 同类修改出现次数
  items: [{ id, status, lineNum, fullLine, prevLine, nextLine, ... }]

```

## 四、审核列表问题修复（本轮第二个迭代）

### 问题1：组预览不显示变更部分

**现象**: 组头部预览显示了文本的开始部分，但如果变更发生在文本中段或末尾，用户看不到要改的内容。

**原因**: `createGroupElement` 头部使用 `renderInlineDiff` 渲染**全文** diff，用户需要滚动查找高亮部分。

**修复**: `diff-utils.js` 新增 `renderDiffPreview(text1, text2, contextLen=20)`:
1. 运行 diff 算法找到第一个和最后一个变更位置
2. 提取变更区域 + 两侧各 20 字符上下文
3. 截断处用 `…` 标识（`.diff-trunc` 样式: 浅色+粗体+大间距）
4. `review.js` 组头部改用 `renderDiffPreview`

对比效果：

## 五、关键发现

### 5.1 preprocess.go vs basic_cleaner.go 的 control char 不一致

两个模块都有清理控制字符的逻辑，但正则不同：

| 模块 | 正则 | 保留 \n \r \t |
|------|------|:---:|
| `preprocess.go:341` (修复前) | `[\x00-\x1F\x7F]` | ❌ |
| `preprocess.go:341` (修复后) | `[\x00-\x08\x0B\x0C\x0E-\x1F\x7F]` | ✅ |
| `basic_cleaner.go:160` | `[\x00-\x08\x0B\x0C\x0E-\x1F\x7F]` | ✅ |

`basic_cleaner.go` 始终是正确的，`preprocess.go` 是另一个开发人员在另一个时间写的，两者未保持一致。

### 5.2 main.js 与 modules/*.js 的函数冲突

`main.js` 是遗留的单体 JS 文件，`modules/*.js` 是新模块化架构。两者都声明了同名全局变量/函数（`currentFileMd5`、`reviewItems`、`pollingTimer`、`showSection`等），可能造成意外的覆盖和 bug。

### 5.3 后端修改类型不直接反映在前端

后端实际输出 6 种类型，但前端原来的映射表只有 5 种（`typo`、`duplicate_paragraph`、`advertisement`、`grammar`、`style`），缺少 `typo_correction`、`character_correction`、`text_deletion`、`text_insertion`、`llm_fix` 的映射。这些类型在数据库中有数据，但前端显示为空或原始字符串。
