# 单元测试计划

## 1. 测试概述

单元测试（Unit Testing）针对项目中各个核心模块的独立函数和类进行测试，确保每个组件的正确性。

## 2. 测试范围

根据项目结构，测试以下核心模块：

| 模块 | 文件 | 测试重点 |
|------|------|----------|
| 配置模块 | internal/config/config.go | 配置加载、环境变量解析 |
| 文件模块 | internal/file/ | MD5计算、文件名解析 |
| 数据库模块 | internal/database/ | CRUD操作、数据验证 |
| 预处理模块 | internal/processor/preprocess/ | 编码检测、文本清洗 |
| 后处理模块 | internal/processor/postprocess/ | 文本重组、内容输出 |
| 向量检测模块 | internal/processor/vector_detector.go | 相似度计算、去重检测 |
| 规则模块 | internal/processor/rules/ | 规则匹配、替换逻辑 |
| 审核模块 | internal/review/ | 审核状态管理 |

## 4. 测试执行

### 4.1 执行方式

```bash
# 进入项目根目录
cd /home/gao/Builds/txtCleaning

# 执行所有单元测试
go test -v ./...

# 执行指定模块测试
go test -v ./internal/file/
go test -v ./internal/database/
go test -v ./internal/processor/preprocess/
```

### 4.2 测试脚本

```bash
# 使用测试脚本
cd /home/gao/Builds/txtCleaning/testing/unit_testing
```

## 7. 注意事项

1. 测试应独立运行，不依赖外部服务（LLM API等）
2. 测试数据应使用临时文件或内存数据库
3. 每个测试函数以 `Test` 开头
4. 使用 table-driven tests 模式提高测试可维护性
5. 涉及文件操作的测试应清理临时文件
