🔴 严重 限流响应头数值转换错误
问题位置：web/backend/middleware/rate_limit.go:195-197
问题描述：string(rune(remaining)) 会把数字 99 转成字符 c，导致 X-RateLimit-Remaining 响应头不可用，测试也已失败。
严重程度：🔴 严重
修复建议：使用 strconv.Itoa(remaining) 输出十进制字符串，并将 X-RateLimit-Limit 改为实际配置值；测试中应使用 Header.Get 校验大小写规范化后的 header。
预估修复时间：10分钟
🔴 严重 API 重试时请求体可能被复用为空
问题位置：internal/external/api.go:363-372
问题描述：重试循环只 clone 请求对象，没有在每次重试前通过 req.GetBody 重建 Body，首次请求失败后后续请求可能发送空 JSON。
严重程度：🔴 严重
修复建议：在 retry 循环内执行 if req.GetBody != nil { clonedReq.Body, err = req.GetBody() }，或把请求创建改成工厂函数，每次重试重新 marshal 并创建新 http.Request。
预估修复时间：45分钟
🔴 严重 HTML 报告接口未转义用户可控字段
问题位置：web/backend/handlers/process.go:722-739
问题描述：buildReportHTML 使用 fmt.Sprintf 直接拼接标题、作者、文件名等字段，上传文件名或元数据包含 HTML 时存在 XSS 风险。
严重程度：🔴 严重
修复建议：改用 html/template 渲染，或至少对所有插值字段使用 html.EscapeString；同时为 ?format=html 增加覆盖恶意文件名的测试。
预估修复时间：1小时
🔴 严重 HTTP Server 未配置基础超时
问题位置：cmd/voidtext/main.go:60-63
问题描述：http.Server 只设置了地址和 Handler，缺少 ReadHeaderTimeout、ReadTimeout、WriteTimeout、IdleTimeout，对慢速连接和资源占用攻击缺少保护。
严重程度：🔴 严重
修复建议：按上传和长轮询场景设置合理超时，例如 ReadHeaderTimeout: 5*time.Second、ReadTimeout: 120*time.Second、WriteTimeout: 120*time.Second、IdleTimeout: 60*time.Second。
预估修复时间：15分钟
