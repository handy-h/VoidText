# 处理流水线

## 1. 流水线概述

五步处理流水线，每步可独立执行，支持进度恢复。

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  步骤1      │───▶│  步骤2      │───▶│  步骤3      │───▶│  步骤4      │───▶│  步骤5      │
│  基础清洗   │    │  向量检测   │    │  LLM修复    │    │  人工审核   │    │  生成文件   │
│ (cleaning)  │    │ (indexing)  │    │ (llm_fix)   │    │  (review)   │    │(finalizing) │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
```

## 2. 步骤详解

### 2.1 步骤1：基础文本清洗 (cleaning)

**入口函数**: `processCleaningStep`

**功能**:
- 编码检测与转换（GBK → UTF-8）
- HTML 实体清理（`&nbsp;`、`&amp;` 等）
- 标点规范化（全角/半角）
- 空白字符规范化
- 繁体转简体（可选）
- 广告移除（正则匹配）

**配置项**:
- `ENABLE_BASIC_CLEANING`: 是否启用
- `TRADITIONAL_TO_SIMPLE`: 繁体转简体
- `BASIC_CLEANING_TOOL`: 清洗工具（regex）

**输出**:
- 清洗后的文本
- 中间版本文件保存到 `data/uploads/{md5}_cleaning.txt`

### 2.2 步骤2：向量索引与检测 (indexing)

**入口函数**: `processIndexingStep`

**功能**:
- 按换行符分割段落
- 生成段落向量（本地计算或 API）
- 计算余弦相似度
- 检测重复段落
- 移除相似度超过阈值的段落

**配置项**:
- `ENABLE_VECTOR_DETECTION`: 是否启用
- `VECTOR_MODEL_TYPE`: 向量模型类型（local/api）
- `VECTOR_SIMILARITY_THRESHOLD`: 相似度阈值（默认 0.95）

**向量计算算法**:
```go
// 余弦相似度
similarity = dotProduct(v1, v2) / (|v1| * |v2|)
// 其中 |v| = sqrt(sum(vi^2))
```

**输出**:
- 去重后的文本
- 中间版本文件保存到 `data/uploads/{md5}_indexing.txt`

### 2.3 步骤3：LLM修复 (llm_fix)

**入口函数**: `processLlmFixStep`

**功能**:
- 按段落分割文本
- 逐段落调用 LLM API 进行修复
- 每段落修复后记录审核项
- 支持本地字典兜底

**配置项**:
- `ENABLE_MODEL_REPAIR`: 是否启用
- `REPAIR_MODEL_TYPE`: 修复模式（api/local）
- `LLM_API_URL`: API 地址
- `LLM_API_KEY`: API 密钥
- `COMPLETION_MODEL_NAME`: 模型名称

**处理流程**:
```go
for i, paragraph := range paragraphs {
    // 1. 更新进度日志
    log("正在修复段落 %d/%d: %s...", i+1, len(paragraphs), firstLine)

    // 2. 调用 API 修复
    repaired, changes := repairer.RepairParagraph(paragraph)

    // 3. 记录修改
    for _, change := range changes {
        reviewItems = append(reviewItems, createReviewItem(change))
    }

    // 4. 更新数据库进度
    UpdateFileStatus(md5, "processing", "llm_fix", percent)
}
```

**API Prompt 示例**:
```
请检查以下中文小说文本中的错别字和语法错误。
只修复错误，不要修改正常的内容。
如果发现错误，请返回"修复后: [修正后的文本]"；
如果没有错误，请返回"无需修复"。

待检查文本：
{paragraph}
```

**输出**:
- 修复建议记录到 `review_items` 表
- 中间版本文件保存到 `data/uploads/{md5}_llm_fix.txt`

### 2.4 步骤4：人工审核 (review)

**入口函数**: 无自动入口（状态变更为 reviewing 后等待用户操作）

**功能**:
- 显示待审核项列表
- 用户逐条操作：通过/拒绝/编辑
- 支持批量操作

**审核操作**:
| 操作 | API | 说明 |
|------|-----|------|
| 通过 | `POST /api/files/:md5/approve` | 接受修改建议 |
| 拒绝 | `POST /api/files/:md5/reject` | 拒绝修改建议 |
| 编辑 | `POST /api/files/:md5/edit` | 手动编辑修改后文本 |
| 恢复 | `POST /api/files/:md5/restore` | 恢复为待审核 |
| 批量通过 | `POST /api/files/:md5/batch-approve` | 批量接受 |
| 批量拒绝 | `POST /api/files/:md5/batch-reject` | 批量拒绝 |

**进度计算**:
```
progress = (total_items - pending_items) / total_items * 100
```

### 2.5 步骤5：生成最终文件 (finalizing)

**入口函数**: `processFinalizingStep`

**触发条件**: 所有审核项状态为 accepted/rejected/edited

**功能**:
- 根据审核结果生成最终文件
- 保存最终版本到版本链
- 更新文件状态为 completed

**输出**:
- 最终文件: `data/uploads/{md5}_final_{timestamp}.txt`
- 版本类型: `final`

## 3. 进度恢复

### 3.1 恢复原理

每个文件的 `files.current_step` 字段记录当前步骤：
- 服务重启后，读取该字段确定从哪一步继续
- 已完成的步骤不会重新执行
- 当前步骤会从头开始（如 LLM 修复会从头处理所有段落）

### 3.2 恢复流程

```go
// 获取当前步骤
record, _ := database.GetFileByMd5(md5)

// 确定要执行的步骤列表
stepsToRun := []string{}
found := false
for _, step := range AllSteps {
    if step == record.CurrentStep {
        found = true
    }
    if found {
        stepsToRun = append(stepsToRun, step)
    }
}

// 依次执行
for _, step := range stepsToRun {
    ProcessStep(md5, step)
}
```

## 4. 错误处理

### 4.1 步骤失败

```go
if err != nil {
    database.UpdateFileStatus(md5, "failed", step, progress, err.Error())
    return nil, err
}
```

### 4.2 服务重启

- goroutine 会随进程结束而终止
- 状态仍为 `processing` 的文件，需要用户点击"继续处理"
- 继续处理会重置状态为 `pending`，从 `current_step` 继续

### 4.3 API 超时

- LLM API 调用设置超时（默认 60 秒）
- 超时后回退到本地字典修复
- 部分段落失败不影响其他段落

## 5. 中间版本

### 5.1 版本命名

| 阶段 | 文件名格式 |
|------|-----------|
| 原始 | `{md5}_original.txt` |
| 清洗后 | `{md5}_cleaning.txt` |
| 索引后 | `{md5}_indexing.txt` |
| LLM修复后 | `{md5}_llm_fix.txt` |
| 最终 | `{md5}_final_{timestamp}.txt` |

### 5.2 版本链记录

每次保存中间版本时，同时记录到 `versions` 表：
- `version_md5`: 当前版本 MD5
- `parent_md5`: 上一个版本 MD5
- `version_type`: original/intermediate/final
- `file_path`: 文件存储路径
