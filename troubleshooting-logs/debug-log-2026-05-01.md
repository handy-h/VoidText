# Debug 2026-05-01: 审核面板纯黑 + 上下文缺失 + 无建议项处理 + 下载文件名

## 问题概述

本次涉及 4 个独立问题：审核面板全黑（JS 模块语法错误）、上下文预览与原文之间的文本丢失、无修改建议项的处理逻辑、下载文件名不含"清洗版"后缀及中文 URI 编码。

---

## 一、审核面板纯黑

### 1.1 问题根因

`review.js` 工作目录版本使用了 **ES Module 语法**（`import/export`），但 HTML 中使用的是 `<script>`（无 `type="module"`），浏览器在解析 `import` 语句时抛出 `SyntaxError`，导致 **整个脚本链断裂**，所有 JS 模块（auth、file-manager、app 等）都无法执行，页面完全空白。

### 1.2 追溯

- Git HEAD 版本是正常的 **IIFE 模式**：`const ReviewModule = (function() { ... })();`
- 工作目录版本已被替换为 ES Module 版本，来源不明

### 1.3 修复

恢复为 HEAD 的 IIFE 版本，并在其基础上重新应用所有功能增强：

| 文件 | 变更 |
|------|------|
| `web/frontend/static/js/modules/review.js` | 恢复到 IIFE 模式，消除 `import`/`export` |

## 二、上下文预览与原文之间的文字缺失

### 2.1 问题根因

当修改项位于一行文本的中间位置时：

- `prevLines` 只显示匹配行**之前**的行
- `original` 只显示改动片段（从行中间开始）
- 匹配行从行首到片段之前的文本**完全不显示**

例如上传文本中的段落：
```
他的脸蒙上了一道阴云。“有人把我的雪橇藏了，找不到了。”他笑着说。“但是我敢说没事儿。这是你丈夫的手枪...
```

`prevLines` 显示前一行，`original` 显示 `敢说没事儿。这是你丈夫的手枪...`，但 `他的脸蒙上了一道阴云……他笑着说。“但是` 完全丢失。

### 2.2 修复

在 `createDiffCard` 中，使用 `fullLine.indexOf(original)` 定位原始片段位置，将 `fullLine` 中 `original` 之前的部分提取为"续行上下文"（`.context-continuation`），渲染在 prevLines 和原文之间：

| 文件 | 变更 |
|------|------|
| `web/frontend/static/js/modules/review.js` | 新增 `fullLine` 前置文本提取与渲染 |
| `web/frontend/static/css/style.css` | 新增 `.context-continuation` 样式（紫色左边框 + → 前缀） |

## 三、无修改建议项的处理逻辑

### 3.1 问题

非删除类型的审核项（typo/semantic 等）的 `SuggestedText` 为空字符串时：

- 前端不显示建议行（`if (sugg)` 为 false）
- 用户点"通过"后，后端 `ApplySuggestion` 用空字符串替换原文 → **原文被删除**
- 实际上点通过和点拒绝的结果一样（都保留原文），展示无意义

### 3.2 修复

**后端**（`pipeline.go`）：新增 `isDeletionType()` 识别三类有意删除型修改（`text_deletion`/`advertisement`/`duplicate_paragraph`），在 `buildSortedChanges` 和 `CheckReviewComplete` 中跳过无建议的非删除类项。

**后端**（`process.go`）：`GetReviewItems` 在 API 响应中过滤掉无建议的非删除类项，前端永远不会看到它们。

**前端**（`review.js`）：建议文本为空时，按类型显示 `（删除）` 或 `（无修改建议）`。

**前端**（`review.js`）：`batchApproveAll`/`batchRejectAll` 补传 `itemIds` 到请求体，修复"无效的请求参数"错误。

**涉及的修改：**

| 文件 | 变更 |
|------|------|
| `internal/processor/pipeline.go` | `isDeletionType`、`buildSortedChanges` 跳过逻辑、`CheckReviewComplete` 跳过逻辑 |
| `web/backend/handlers/process.go` | `GetReviewItems` 过滤无建议项 |
| `web/frontend/static/js/modules/review.js` | 建议行 fallback 文本 + batch 函数传参修复 |

## 四、下载文件名不含"清洗版"后缀

### 4.1 问题根因

`processFinalizingStep` 生成最终文件后：

- 只写入了 `versions` 表（`version_type = "final"`）
- **没有更新** `files.file_path` 和 `files.file_name`
- 下载接口 `DownloadFile` 读取的是 `files.file_path`，指向的是最后一步中间文件（如 `xxx_llm_fix.txt`）

### 4.2 修复

**`processFinalizingStep`**（`pipeline.go`）：
- 最终文件名改为 `{原文件名}_清洗版_{时间戳}.txt`
- 写入文件后通过 `UPDATE files SET file_path=?, file_name=?, status='completed'` 更新数据库记录

**`DownloadFile`**（`files.go`）：
- 将 `url.PathEscape` 改为 `url.QueryEscape`（更符合 RFC 5987）
- `Content-Disposition` 中 `filename*=UTF-8''` 放在 `filename=` 前面

**前端下载**（`file-manager.js`）：
- 文件名提取优先匹配 `filename*=UTF-8''...`，然后用 `decodeURIComponent` 解码
- fallback 到 `filename="..."`

### 4.3 涉及文件

| 文件 | 变更 |
|------|------|
| `internal/processor/pipeline.go` | 最终文件名含"清洗版"后缀 + 更新 `files` 表 |
| `web/backend/handlers/files.go` | `Content-Disposition` 编码与顺序修复 |
| `web/frontend/static/js/modules/file-manager.js` | 前端 regex 优先 `filename*=` |
