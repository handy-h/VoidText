# 阿里云云效平台自动部署说明

## 一、整体架构

```
代码推送 → 云效代码管理 → 流水线触发 → 构建(Go编译) → 部署(目标服务器) → 健康检查
```

## 二、前置准备

### 1. 云效基础设置

| 准备项 | 说明 |
|--------|------|
| 云效组织 | 在 [云效](https://flow.aliyun.com) 创建组织 |
| 代码源 | 将项目推送到云效 Codeup，或关联 GitHub/Gitee 仓库 |
| 主机组 | 在「设置 → 主机组」中添加目标部署服务器（需安装云效 Agent） |
| 环境变量 | 在流水线中配置敏感变量（API Key 等），**禁止硬编码** |

### 2. 目标服务器准备

```bash
# 安装 Go 1.25+（如需在服务器编译）
wget https://go.dev/dl/go1.25.0.linux-amd64.tar.gz
sudo tar -C /usr/local -xzf go1.25.0.linux-amd64.tar.gz
export PATH=$PATH:/usr/local/go/bin

# 创建应用目录
sudo mkdir -p /opt/txtcleaning/{data,models,logs}
sudo chown -R $(whoami) /opt/txtcleaning

# 安装云效 Agent（在云效主机组页面获取安装命令）
```


## 四、构建阶段（Go 编译）

**构建步骤类型**：选择「Go 构建」

**构建配置**：

| 配置项 | 值 |
|--------|-----|
| Go 版本 | go1.25 |
| 构建命令 | 见下方 |
| 构建产物路径 | `txtclean` |

**构建命令**：

```bash
# 设置 Go 环境
go env -w GOOS=linux GOARCH=amd64 CGO_ENABLED=1

# 下载依赖
go mod tidy
go mod verify

# 运行单元测试
go test ./... -v -count=1

# 编译二进制
go build -ldflags="-s -w" -o txtclean ./cmd/txtclean
```

> **原理说明**：
> - `CGO_ENABLED=1`：项目使用 `modernc.org/sqlite`，需要 CGO 支持
> - `-ldflags="-s -w"`：去除调试信息，减小二进制体积约 30%
> - `-count=1`：禁用测试缓存，确保每次全量执行

## 五、部署阶段

**部署步骤类型**：选择「主机部署」

### 1. 主机组选择

选择之前添加的目标服务器主机组。

### 2. 部署配置

| 配置项 | 值 |
|--------|-----|
| 下载制品 | 构建阶段产物 `txtclean` |
| 部署目录 | `/opt/txtcleaning` |
| 部署脚本 | 见下方 |

**部署脚本**：

```bash
#!/bin/bash
set -e

APP_NAME="txtCleaning"
APP_DIR="/opt/txtcleaning"
APP_BINARY="${APP_DIR}/txtclean"
PID_FILE="${APP_DIR}/pid.txt"
BACKUP_DIR="${APP_DIR}/backups"

# 停止旧服务
if [ -f "$PID_FILE" ]; then
  OLD_PID=$(cat "$PID_FILE")
  if ps -p "$OLD_PID" > /dev/null 2>&1; then
    echo "停止旧服务 (PID: ${OLD_PID})..."
    kill "$OLD_PID"
    sleep 3
    if ps -p "$OLD_PID" > /dev/null 2>&1; then
      kill -9 "$OLD_PID"
    fi
  fi
  rm -f "$PID_FILE"
fi

# 备份旧二进制
if [ -f "$APP_BINARY" ]; then
  mkdir -p "$BACKUP_DIR"
  cp "$APP_BINARY" "${BACKUP_DIR}/txtclean_$(date +%Y%m%d%H%M%S)"
  # 只保留最近3个备份
  ls -t "${BACKUP_DIR}"/txtclean_* | tail -n +4 | xargs -r rm -f
fi

# 替换二进制（云效会将制品下载到指定目录）
chmod +x "${APP_DIR}/txtclean"

# 确保 .env 文件存在
if [ ! -f "${APP_DIR}/.env" ]; then
  echo "警告: ${APP_DIR}/.env 不存在，请手动创建"
  exit 1
fi

# 启动新服务
cd "$APP_DIR"
nohup ./txtclean > "${APP_DIR}/logs/app.log" 2>&1 &
echo $! > "$PID_FILE"

# 等待启动并检查
sleep 3
NEW_PID=$(cat "$PID_FILE")
if ps -p "$NEW_PID" > /dev/null 2>&1; then
  echo "服务启动成功 (PID: ${NEW_PID})"
else
  echo "服务启动失败，查看日志："
  tail -50 "${APP_DIR}/logs/app.log"
  exit 1
fi
```

## 六、验证阶段

**验证脚本**（健康检查）：

```bash
#!/bin/bash
APP_DIR="/opt/txtcleaning"

# 从 .env 读取端口
PORT=$(grep "^PORT=" "${APP_DIR}/.env" | cut -d'=' -f2)
PORT=${PORT:-8080}

# 健康检查（最多重试5次）
MAX_RETRIES=5
RETRY_INTERVAL=3

for i in $(seq 1 $MAX_RETRIES); do
  HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" "http://127.0.0.1:${PORT}/" || echo "000")
  if [ "$HTTP_CODE" = "200" ]; then
    echo "健康检查通过 (HTTP ${HTTP_CODE})"
    exit 0
  fi
  echo "健康检查第${i}次失败 (HTTP ${HTTP_CODE})，${RETRY_INTERVAL}秒后重试..."
  sleep $RETRY_INTERVAL
done

echo "健康检查失败，服务可能未正常启动"
tail -50 "${APP_DIR}/logs/app.log"
exit 1
```

## 七、环境变量与敏感信息管理

在流水线 **「变量与缓存」** 中配置：

| 变量名 | 类型 | 说明 |
|--------|------|------|
| `LLM_API_KEY` | 加密 | LLM API 密钥 |
| `VECTOR_MODEL_API_KEY` | 加密 | 向量模型 API 密钥 |
| `PORT` | 普通 | 服务端口（默认 8080） |
| `DATA_DIR` | 普通 | 数据目录路径 |
| `LLM_API_URL` | 普通 | LLM API 地址 |
| `VECTOR_MODEL_URL` | 普通 | 向量模型 API 地址 |

**在部署脚本中生成 `.env` 文件**（在部署脚本开头添加）：

```bash
cat > "${APP_DIR}/.env" << EOF
PORT=${PORT}
DATA_DIR=${APP_DIR}/data
MODELS_DIR=${APP_DIR}/models
MAX_FILE_SIZE=104857600
BACKUP_KEEP_DAYS=7
ENABLE_BASIC_CLEANING=true
BASIC_CLEANING_TOOL=regex
TRADITIONAL_TO_SIMPLE=false
ENABLE_VECTOR_DETECTION=true
VECTOR_MODEL_NAME=all-MiniLM-L6-v2
VECTOR_MODEL_TYPE=local
VECTOR_SIMILARITY_THRESHOLD=0.95
VECTOR_MODEL_URL=${VECTOR_MODEL_URL}
VECTOR_MODEL_API_KEY=${VECTOR_MODEL_API_KEY}
ENABLE_MODEL_REPAIR=true
REPAIR_MODEL_TYPE=api
LLM_API_URL=${LLM_API_URL}
LLM_API_KEY=${LLM_API_KEY}
COMPLETION_MODEL_NAME=qwen-max-2025-01-25
COMPLETION_TEMPERATURE=0.3
COMPLETION_MAX_TOKENS=2048
EOF
```

> **安全说明**：加密变量在日志中自动脱敏，不会明文暴露。

## 八、回滚策略

### 方式一：重新运行历史流水线

在云效流水线历史记录中，选择上一个成功的流水线重新运行。

### 方式二：手动回滚二进制

```bash
APP_DIR="/opt/txtcleaning"
PID_FILE="${APP_DIR}/pid.txt"

# 停止当前服务
if [ -f "$PID_FILE" ]; then
  kill "$(cat "$PID_FILE")" 2>/dev/null
  rm -f "$PID_FILE"
fi

# 回滚到上一个版本
LATEST_BACKUP=$(ls -t "${APP_DIR}/backups"/txtclean_* | head -1)
cp "$LATEST_BACKUP" "${APP_DIR}/txtclean"
chmod +x "${APP_DIR}/txtclean"

# 重启
cd "$APP_DIR" && nohup ./txtclean > logs/app.log 2>&1 &
echo $! > "$PID_FILE"
```

## 十、注意事项

1. **CGO 依赖**：项目使用 `modernc.org/sqlite`，构建环境需安装 `gcc`，目标服务器需有 `glibc`
2. **数据持久化**：`/opt/txtcleaning/data` 目录包含 SQLite 数据库，部署时**不要覆盖**
3. **CORS 配置**：当前 CORS 仅允许 `localhost:8080`，生产环境需在 [server.go](file:///home/gao/Builds/txtCleaning/web/backend/server.go) 中添加实际域名
4. **前端静态文件**：部署时需确保 `web/frontend/` 目录与二进制在同一相对路径下，或修改路由配置
5. **端口冲突**：确保目标服务器 8080 端口未被占用
6. **磁盘空间**：上传文件和数据库在 `data` 目录，需定期监控磁盘使用
