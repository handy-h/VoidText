## 三、问题分析

### 可能的原因

1. **Ollama runner 进程卡住**
   - runner 进程（PID 197445）存在但不响应 generate 请求
   - 可能是模型加载后内部状态异常

2. **模型首次加载时间过长**
   - 7B 模型首次加载到内存可能需要 30-60 秒
   - 如果每次请求都重新加载，会超时

3. **Ollama 版本兼容性问题**
   - 当前 Ollama 版本可能与模型格式不兼容
   - GGUF 格式模型可能需要特定版本的 Ollama

4. **系统资源不足**
   - 内存不足导致模型加载缓慢
   - GPU 显存不足（RTX 2060 6GB）导致回退到 CPU 推理

5. **网络/防火墙问题**
   - 虽然监听在 127.0.0.1，但可能有防火墙规则阻止

## 五、排查结果（2026-04-24 更新）

### 根因定位

**核心问题**: 系统没有 NVIDIA GPU，Ollama 使用 **CPU 推理**

**证据**:
```bash
$ nvidia-smi
NVIDIA-SMI has failed because it couldn't communicate with the NVIDIA driver.
```

**性能数据**:
- `/api/generate` 成功响应，但耗时 **131 秒**
- 生成 1332 个 token 需要 129.8 秒
- 模型加载时间仅 0.1 秒（已缓存）

**结论**: CPU 推理 7B 模型非常慢，每个 chunk 处理需要 100-150 秒，远超原来的 60 秒超时设置。

### 解决方案

将 `.env` 中的超时时间从 120 秒增加到 **180 秒**:
```env
LOCAL_MODEL_TIMEOUT=180
```

**注意**: 
- CPU 推理: 100-150 秒/chunk
- GPU 推理: 10-30 秒/chunk
