换行符修复功能设计

版本: v1.0 | 更新日期: 2026-05-15 | 状态: 已实施

1. 需求背景

问题描述

部分小说 TXT 文件缺少段落分隔符（换行符），整篇文本连成一片，严重影响阅读体验。典型表现：

  • 段落之间没有空行分隔
  • 对话内容与叙述混在一起
  • 章节标题嵌入在正文中
示例
狼窝里安了窃听器。」一辆抛锚的汽车给哥拉家族带来希望。族长使用调虎离山计智取窃听器。居住在白塔山上的几十只兔子同属于哥拉家族。哥拉家族祖祖辈辈定居在白塔山上。按兔家族繁衍的速度来计算，哥拉家族的数量早该逾万了。

上述文本应被自动分割为多个段落，以提升可读性。

2. 功能设计

2.1 自动检测

检测策略

通过分析换行符密度判断文本是否缺少段落分隔：

  • 密度阈值: 每 300 个字符少于 1 个换行符
  • 内容要求: 文本长度 ≥ 100 字符，且包含中文标点（句号、引号等）
  • 跳过条件: 已有足够换行符的文本不触发修复

2.2 智能分段规则

规则 触发条件 说明
章节标题识别 ◇ 一 ◇、第X章、一、二、 自动识别常见章节标题格式，将其独立成段
对话结束检测 句号/感叹号/问号 + 引号闭合 识别对话结束位置，在引号闭合后分段
句子结束分段 句号 + 非引号开始的中文字符 在句号后检查后续内容，判断是否为新段落
连续省略号 三个及以上省略号 识别段落结尾的省略号
短段落合并 段落长度 < 20 字符 自动合并过短的段落，避免碎片化

2.3 配置选项

用户可控
  • 前端开关: 规则配置界面中的"换行符修复"复选框
  • 默认值: 启用（enableNewlineFix: true）
  • 配置存储: 数据库 files.rules_config 字段（JSON 格式）

3.3 核心数据结构

// NewlineFixResult 换行符修复结果
type NewlineFixResult struct {
    Content  string              `json:"content"`
    Original string              `json:"original"`
    Changes  []preprocess.Change `json:"changes"`
    Stats    map[string]int      `json:"stats"`
}

// NewlineFixer 换行符修复器
type NewlineFixer struct {
    EnableAutoFix      bool  // 启用自动修复
    MinParagraphLength int   // 最小段落长度（字符数）
    MaxParagraphLength int   // 最大段落长度（字符数）
}

3.4 Pipeline 集成点

执行位置

在 processCleaningStep 中，BasicCleaner.Clean() 之后、自定义规则应用之前执行。

// 换行符修复：检测并修复缺失的段落分隔
if rulesConfig.EnableNewlineFix {
    newlineFixer := NewNewlineFixer()
    newlineResult := newlineFixer.Fix(cleanResult.Content)
    if len(newlineResult.Changes) > 0 {
        cleanResult.Content = newlineResult.Content
        cleanResult.Changes = append(cleanResult.Changes, newlineResult.Changes...)
        for k, v := range newlineResult.Stats {
            cleanResult.Stats[k] = v
        }
    }
}

4. 处理流程

流程图
输入文本
    ↓
[自动检测] 换行符密度是否足够？
    ├─ 是 → 跳过修复，返回原内容
    └─ 否 ↓
[智能分段] 基于标点符号和上下文分割段落
    ↓
[短段落合并] 合并长度 < 20 字符的段落
    ↓
输出修复后文本 + 变更记录

5. 测试覆盖

测试用例 预期结果
缺少换行符的中文小说 自动分割为多个段落
正常换行的文本 跳过修复，保持原样
带有章节标题的文本 章节标题独立成段
带有对话的文本 对话结束处正确分段
空内容/短内容 跳过修复

6. 后续优化方向

可扩展性
  • 支持更多章节标题格式（如罗马数字、阿拉伯数字）
  • 基于 LLM 的智能分段（处理复杂上下文）
  • 用户自定义分段规则（通过配置界面）
  • 分段置信度评估（低置信度项进入审核流程）
